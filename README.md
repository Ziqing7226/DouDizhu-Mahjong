# 斗地主 & 麻将 · AI 单机版

纯前端实现的棋牌合集：**斗地主**（三档难度，两名 AI 对手）与**四人麻将**
（吃碰杠胡、番种计分、三档难度 AI）。无需联网、无需安装依赖，
**双击 `index.html` 即可开始**。

进入页面先在**游戏模式大厅**挑选斗地主或麻将（左上角金色「🎮 游戏大厅」按钮块
随时返回切换）；选定后进入对应模式的**选场大厅**（新手场 / 高手场 / 大师场），选好立即开局。
每局结束后可点「换个场次」（或关闭结算/战绩弹窗）随时回到大厅更换对手；
「再来一局」则保持同一批对手直接续战 —— 回大厅才会换新一批随机网名的牌友。

## 快速开始

```
双击 index.html          # 推荐：直接用浏览器打开
```

不需要本地服务器，所有模块用普通 `<script>` 标签加载（刻意没用 ES Module，
避免 `file://` 协议下的跨域限制）。

想跑测试需要 Node（可选）：

```bash
node tests/test-core.js            # 规则引擎 + AI 逻辑回归（442 项断言）
node tests/test-core.js --full     # 扩大样本（1885 项断言：1800 次决策 + 200 局互搏）
node tests/test-ui.js              # 无浏览器端到端（完整对局 + 渲染 + 交互 + 音效 + 存档）
node tests/test-ui.js --full       # 扩大到 40 局
```

## 麻将玩法

- **行牌**：136 张牌（万/条/筒 1-9 与 东南西北中发白 各 4 张），四人，
  摸牌 → 打牌循环；别家打牌时可 **胡 / 杠 / 碰**，下家可 **吃**
  （优先级 胡 > 杠 > 碰 > 吃）；手中四张相同可暗杠，杠后从墙尾补牌
- **胡牌**：四组面子（顺子/刻子）+ 雀头；门清时七对、国士无双也可胡
- **番种**：平胡 1 番起，累加自摸 / 门前清 / 杠上开花 / 碰碰胡 / 混一色 /
  七对 / 清一色 / 字一色 / 地胡 / 天胡 等；得分 = 底分 100 × 总番数，
  自摸三家各付、点炮者一家付，庄家参与结算翻倍；荒庄不计分
- **AI 难度**（三档核心原理与斗地主同构）：新手凭手感；
  高手记牌推演 —— 按未出现的牌算进张，最小向听 + 最大受入选牌；
  大师为完全信息 AI（能看到所有人手牌，作弊难度）：精确算出每家是否听牌、
  听哪些张，绝不含糊打出现铳，并按真实牌墙余量计算进张，提示按钮禁用。
  加杠宣言可被抢杠胡；局终亮出各家手牌（对局过程中不显示）
- **余牌器**：实时显示 34 种牌各剩几张未出现

## 玩法

- **选场**：开局前在大厅选择 新手场 / 高手场 / 大师场，难度即刻生效
- **叫分抢地主**：1 / 2 / 3 分，叫 3 分立即锁定，三家都不叫则重新发牌
- **加倍**：两个农民先选（加倍 ×2 / 超级加倍 ×4），地主随后决定是否反加
- **出牌**：地主先出，逆时针轮转；两家都不要则由最后出牌者重新领出
- **倍数**：叫分倍数 × 加倍 × 每个炸弹/王炸（×2）× 春天（×2）
- **计分**：地主 ±2×底分×倍数，农民 ±底分×倍数

支持的牌型（14 种）：单张、对子、三张、三带一、三带二、顺子、连对、
飞机、飞机带单、飞机带对、四带二、四带两对、炸弹、王炸。
2 和王不参与顺子 / 连对 / 飞机；同类型同长度才能比大小。

## AI 设计

地基是一个**手牌拆解器**：把一手牌拆成「最少几手能打完」的组合序列，
用记忆化 DFS + 节点预算求解，超预算自动回退贪心解。AI 的绝大多数判断都建立在
「出掉这手之后还剩几手」这个量上。

| 档位 | 在中等档之上额外具备 |
|------|---------------------|
| **简单** | —（出牌偏随机，多数时候直接不要，不用炸弹，不记牌） |
| **中等** | 基准：贪心拆牌算手数，会压牌、会留炸弹，农民间会配合 |
| **困难** | **记牌推算** + **残局蒙特卡洛推演** + **必胜链搜索** + **农民定位配合** |
| **大师** | 完全信息 AI（能看到所有人手牌），精确封堵逃牌、准确找出必胜出牌链 |

### 困难档的关键机制

- **记牌**：未出现的牌 = 54 − 自己手牌 − 已出牌，必然全在对手手上。
  据此可以**精确**回答「对手压不压得起这一手」（覆盖全部 14 种牌型），而不是估概率
- **必胜链搜索**：如果每一手都打「对手压不起」的牌，我就永远保住先手、
  对手一张都出不去直到我走完 —— 这是**充分条件**下的必胜。用记忆化 DFS 找这条链，
  找到就照着打
- **残局蒙特卡洛推演**：残局（各家 ≤9 张）时，把未知牌随机补全给对手，
  再用快速策略把整局推演到底，按胜率选出手（含「不要」这个选项一起比）
- **农民定位配合**：上家（我出完就轮到地主）放小喂队友、攒大牌控场；
  下家（地主出完就轮到我）顶牌耗地主，不送小单张让地主轻松过牌

### 强度是怎么测出来的

`tests/` 下有一套专门的强度测量工具，因为**凭手感调参会调错方向**：

```bash
node tests/bench-ai.js 300                # 三档混战，看净积分
node tests/duel.js hard normal 400        # 固定牌局配对决斗（0 号位 A，1/2 号位 B）
node tests/teams.js 200                   # 团队对抗：固定「地主 vs 农民×2」四种组合
node tests/ab-test.js                     # A/B：并行对比多个特性开关
node tests/sweep.js                       # 残局阈值扫描
node tests/sweep2.js                      # 跟牌阈值扫描
```

要点：

- **必须用固定牌局**（种子化洗牌）。随机发牌时 200 局的标准误约 ±0.1，
  而我们关心的强弱差异也就 0.1 量级，根本分不清
- **必须做自检**：`duel.js normal normal 250` 实测差异 t=−0.09（≈0），
  说明工具本身无偏，测出来的差异才可信

实测结论（每局净积分，固定牌局）：

| 对比 | 结果 |
|------|------|
| 简单 vs 中等 | 差距极大（−0.73 vs +0.33），简单档是明显的送分档 |
| 困难 vs 中等 | +0.075（方向一致为正，但未达统计显著） |
| 大师 vs 中等 | 与困难同量级；AI 互搏已到噪声极限 |

单次决策耗时：困难档开局约 50ms、残局 <1ms（浏览器里配合 0.7~1.3s 思考延时，无卡顿）。

### 一个反直觉的教训

优化过程中我加了 5 类启发式（绝张优先、逃牌封堵、强制拦截、保先手加成等），
**固定牌局 A/B 实测全部是负收益**，最差的一档达到 t=−3.35（统计显著地变差）。
同样地，把蒙特卡洛推演开到全程也会明显掉分（−0.885）——
因为推演里后续用的是简陋贪心策略，等于在评估「我接下来变笨的话哪手最好」，
指标本身就被带偏了，再叠加采样噪声挑最大值（赢者诅咒）。

这些机制的代码都保留在 `ai.js` 里但默认关闭（见 `AI.FEAT`），
注释里写清了实测结论，方便后续继续调优而不是重蹈覆辙。

## 其他功能

- **手牌拖动连选**：按住任意一张牌横向拖动，划过的所有牌统一处理——
  按下的是未选牌则全部选中，按下的已选中则全部取消。命中按每张牌的
  可见条带精确计算（叠放遮挡不会选偏），快速甩动时中间跳过的牌也会补上；
  原地单击仍是原来的选中/取消
- **出牌语音播报**：任何一方叫分（一分/两分/三分/不叫）、叫地主、
  加倍/超级加倍/不加倍、出牌（“对二”“三带一”“顺子”）、不要时都会播报，
  男女声按座位分配（玩家女声、下家男声、上家女声；系统只有一个中文音色时
  自动用音高/语速拉开反差），语速略快、音高带随机起伏，轻快不机械。
  顶栏 🗣 独立开关，浏览器不支持语音合成时自动静默
- **出牌提示**：循环切换所有可出的组合
- **记牌器**：实时显示各点数还有几张未出现
- **战绩统计**：总场次 / 胜率 / 地主与农民分项胜率 / 连胜 / 积分，本地持久化
- **背景音乐**：纯 WebAudio 合成的原创中式五声音阶循环旋律，无任何外部音频文件。
  平时轻快活泼（拨弦 + 笛声 + 低音 + 轻打击乐），有人快走完或倍数飙升时
  在**小节边界**自动切换紧张型旋律。顶栏独立开关 + 音量滑块，与音效分开，设置持久化
- **动画与音效**：发牌飞入、出牌上桌、炸弹震屏、春天横幅；
  音效用 WebAudio 实时合成，不依赖任何音频文件
- **倒计时**：玩家回合 30 秒，超时自动不要 / 自动出最小的一手
- **移动端适配**：手机浏览器打开自动识别（触屏 + UA，iPadOS 按触控点识别），
  竖屏时显示「请横屏」引导页，横屏后把整块牌桌等比缩放并按屏幕比例
  拉高铺满视口；桌面端布局不受影响。调试可加 `?mobile=1` / `?mobile=0` 强制开关

快捷键：`Enter` 出牌，`空格 / Esc` 不要，`H` 提示。

## 测试

两套测试都围绕「不变量 + 长时程」设计，而不是只点几下：

- **test-core.js**：牌型识别边界（如 `333444555666` 必须识别为四连飞机而非飞机带三单）、
  大小比较、压制枚举、拆解结果合法性校验、三档 AI 决策冒烟、
  以及 AI 互搏 200 局（校验无死循环、胜率落在合理区间）
- **test-ui.js**：用极简 DOM 桩 + 虚拟时钟把整套脚本原样跑起来，
  验证叫分→加倍→出牌→结算全链路，每步校验牌数守恒、无重复牌、手牌有序，
  并覆盖渲染层、按钮交互、弹窗、边界场景（三家不叫重发、20 张手牌渲染）、
  音效合成（带 `AudioContext` 桩真正跑一遍）、存档读写，
  以及语音播报文本与拖动连选（模拟 pointer 事件流）

写测试时踩到并修复过真实缺陷，其中一个是「拆解缓存串手牌导致对局死循环」——
200 局互搏里有 3 局跑不完，靠手点几乎不可能复现。
